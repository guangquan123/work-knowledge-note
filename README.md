# work-knowledge-note

把实际工作案例、踩坑经历、流程经验复盘成可复用的工作经验笔记。重点是「把经验说清楚、以后怎么做」。

适用于 DeepWorks / opencode 的自定义 Skill，随用随沉淀，一份经历一份标准做法。

## 一、它能做什么

| 输入 | 输出 |
| --- | --- |
| 一次真实经历（口述或聊天记录/邮件/纪要等材料） | 一份结构化工作经验笔记（Markdown） |
| 一个踩坑过程（卡在哪、谁负责、怎么解） | 「标准做法 + 避坑清单 + 联系人清单」三件套 |

笔记直接可用：本地归档、转 Word/PDF、转飞书文档。

## 二、笔记长什么样（编号标题体系）

```
# YYYYMMDD {主题}

> 记录：YYYY-MM-DD

{导语段一}：背景与一句话结论
{导语段二}：规则与卡点根源

## 一、标准做法            ← 全篇重点，按阶段分块
### 1.1 {环节名}          ← 有序列表，按执行顺序
### 1.2 {环节名}
### 1.3 卡点排查          ← 表格：现象 | 原因 | 怎么办

## 二、避坑清单            ← 每条 = 坑一句 + 规避一句
## 三、联系人清单           ← 表格：环节 | 找谁 | 什么事
```

设计要点：

1. 一级标题编号 + 名词化（一、标准做法 / 二、避坑清单 / 三、联系人清单），不用口语动词短语
2. 二级标题编号统一（1.1 / 1.2 / 1.3），命名用「{名词}环节 / {名词}清单」
3. 导语至少两段：段一背景与结论，段二规则与根源，不连排成长段落
4. 操作步骤用有序列表，避坑条目用无序列表
5. 表格只用于两处：卡点速查表、联系人清单
6. 有依赖链或流程关系必配画板，放导语后正文前

## 三、怎么用

### 安装

把 `SKILL.md` 放进你的 Skill 目录（DeepWorks 项目级位置）：

```
.opencode/skills/work-knowledge-note/SKILL.md
```

### 触发词

说这些就会自动调用：

- 沉淀经验笔记 / 总结成工作知识笔记
- 复盘这个案例以后复用
- 记录这次踩坑 / 工作笔记

### 使用姿势

- 直接讲经历：什么场景、卡在哪、怎么解决的、哪些是坑
- 或贴已有材料：聊天记录、邮件、纪要、乱稿，由 Skill 去粗取精

不需要你提供任何格式，只讲事实。

## 四、写作纪律

1. 第一目标是把「标准做法」写清楚，其他一切为此服务
2. 先结论；导语段一一段话讲完核心，不铺垫
3. 不写时间线、聊天记录、来回沟通过程，不挂依据引用
4. 讲人话：短句、直接；表格只用在速查和联系人这种天生适合表格的地方
5. 没把握的事实不写进笔记；不用 emoji，不注水
6. 联系人只写岗位和职责，不写个人隐私信息

## 五、适用边界

| 场景 | 用哪个 |
| --- | --- |
| 工作经验沉淀（本 Skill） | work-knowledge-note |
| 每日会话总结与知识卡片 | session-knowledge-extractor |
| 会议纪要 | summarize-meeting |
| 调研纪要 | 02-04-deepexi-research-minutes |

## 六、转飞书文档经验

- 标题用 `YYYYMMDD {主题}`，保留编号标题体系、表格与画板
- 画板用 `<whiteboard type="svg">` 输入；mermaid 内联转换在 CLI 上不可靠（常见 `2107 Whiteboard content parse failed`），SVG 输入稳定
- 推荐流程：空画板占位拿 token → 再用 SVG 覆盖写入
